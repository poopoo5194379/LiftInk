# LiftInk 笔记系统 V0.2 执行顺序

2026-11-02。基线：V0.1 已有本机文档、钢笔/荧光笔、整笔迹橡皮、会话内撤销/重做、图片、应用内区域截图与置顶贴图。当前正式页仍以 SVG 绘制笔迹；真实数位板、macOS 与大文档性能尚无验收结果。[V0.1 实施报告](LIVE-EDITOR-V01-REPORT.md)

## 下一步：先把文档做可靠

| 阶段 | 工作 | 可验收结果 |
| --- | --- | --- |
| A · 保存与恢复 | 把首页笔记索引和文档写入收敛到一个存储模块；明确提交顺序、保存失败提示、备份/恢复和格式版本迁移；处理图片资源引用与孤儿文件。 | 连续编辑、切页、关窗及强制退出后，最近一次**已确认保存**的操作可恢复；损坏文件不被新空白数据覆盖；缺失图片有明确提示。 |
| B · 坐标与渲染 | 固定页面坐标比例，统一缩放/平移/命中；把实时落笔和已提交笔迹分层。以 Canvas 2D + 缓存为首个对照方案，按可见区域绘制并加入空间索引。 | 25%/100%/400% 缩放下笔尖、橡皮、选区与显示位置一致；1千/1万/5万条笔迹记录 p50/p95 绘制时间、内存和笔到屏延迟，再决定是否需要更深的渲染改造。 |
| C · 实机数位板 | 在输入实验台和正式笔记页对照鼠标/笔、悬停、轻重压力、侧键/笔尾、Space/Alt 与失焦恢复。记录设备、驱动、Windows Ink 与显示缩放。 | 无误落墨或悬挂笔迹；压力和按钮映射有实测记录；正式页与实验台的关键行为一致。 |

A 是下一轮代码工作的起点；B 可以先用合成输入推进，C 的最终验收需要实际数位板。B 的目标是测出瓶颈再选实现，不预设必须换成某个库。[tldraw 性能说明](https://github.com/tldraw/tldraw/blob/main/apps/docs/content/sdk-features/performance.mdx)描述了视口裁剪与空间索引；[MDN Canvas 优化指南](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Optimizing_canvas)提供了分层和预渲染的可比较方案。

## 接着补齐日常编辑

2026-11-03 的[竞品对照](COMPETITOR-RESEARCH-2026.md)补充两个排序判断：基础编辑稳定后，应尽早交付 PDF/PNG 导出与可移植备份；选择与页面阶段需要为连续翻页、书签和目录预留结构。PDF 批注可作为后续独立阶段，以只读 PDF 底图加笔迹实现，不等同于修改 PDF 原有内容。下表仍记录原阶段划分，具体优先级以竞品对照的差距表为补充。

| 阶段 | 工作 | 可验收结果 |
| --- | --- | --- |
| D · 选择与页面 | 套索选多条笔迹、移动/缩放、复制/剪切/粘贴；页面删除、重排、逐页纸张设置；所有动作并入撤销历史。 | 一次拖动只占一个撤销步骤；跨页选择不会串页；删除页面后可撤销并恢复原顺序。 |
| E · 书写工具 | 局部橡皮、钢笔参数与颜色、荧光笔叠加；文本批注作为下一种元素加入同一文档模型。 | 擦除和文本编辑不破坏相邻笔迹或图片；撤销粒度符合用户动作；导入旧版本文档仍能打开。 |
| F · 截图贴图完善 | 桌面级选区、显示器选择与不同 DPI、多屏边界；置顶贴图的复制/保存/贴回笔记、关闭与窗口恢复。 | Windows 多屏下选区像素不偏移；取消不生成资源；macOS 授权拒绝时有清楚反馈。[Electron 屏幕捕获](https://www.electronjs.org/docs/latest/api/desktop-capturer/) |
| G · 交付 | 单页/整篇 PNG、PDF 导出；Windows/macOS 打包、首次启动、升级与数据备份验证。 | 导出与页面预览一致；安装版不依赖开发目录；升级后笔记可正常读取。 |

## 本轮不展开

OCR、PDF 编辑、云同步、协作和完整数据库。它们会扩大文件格式、权限与迁移成本，待 A–G 的单机笔记闭环稳定后再单独设计。

## 下一次施工的具体切片

1. 为保存流程写故障测试：模拟写入失败、进程意外退出、损坏目录文件和缺失图片；记录当前结果。
2. 将索引和文档的读写合并到一个带版本与恢复策略的存储模块，保留现有最小权限 IPC。
3. 把“保存中 / 已保存 / 保存失败”绑定到同一提交序号，并做退出时待写入处理。
4. Playwright 重开应用验证标题、目录、页面、笔迹与图片；继续使用隔离数据目录，不采集真实桌面内容作测试截图。

这一步完成后，再进入 B 的渲染与坐标重构，避免在不可靠的保存基础上继续增加编辑命令。
