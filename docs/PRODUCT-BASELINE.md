# LiftInk 产品基线（一页纸）

更新：2026-11-03。状态：开发中，未达到公开发布标准。本文是产品判断与当前范围，不代表用户研究结论。现状以代码和[开发优先级](DEVELOPMENT-PRIORITIES-2026-11-03.md)为准。

| 问题 | 当前答案 |
| --- | --- |
| 为谁做 | 首批验证对象：在 Windows 桌面使用数位板、需要长期整理手写学习或工作笔记的人。macOS 是后续验证平台。尚无访谈数据证明这一群体的规模或付费意愿。 |
| 核心任务 | 新建多页笔记 → 用笔写和修改 → 自动保存 → 关掉重开 → 导出给别人。 |
| 核心痛点 | 桌面手写工具若存在落笔错位、保存不确定、长笔记难编辑或无法导出，就不能成为可靠的日常笔记。以上是待访谈验证的假设。 |
| 产品主张 | 先把本地优先的桌面数位板书写、可恢复编辑和可带走的文件做好，再扩展资料批注和学习功能。 |
| 差异化假设 | 面向桌面大屏和数位板的输入细节；保存状态清楚；本地文件可恢复与导出。当前尚未通过实机测试和用户对照测试证明差异化。 |
| 当前阶段 | 本地文档、单页书写、多页切换、整笔橡皮、图片与截图、会话内撤销/重做已接入；保存恢复首轮完成。坐标/性能、真实数位板、导出、完整页面编辑仍未验收。 |
| MVP 成功定义 | 真实数位板用户可完成上述核心任务，在声明支持的设备上无笔迹错位；已确认保存的内容重开存在；PDF 导出与预览一致。具体量化阈值待基准测试与首轮试用设定。 |

## 范围决定

- **P0 是“可发布的最小闭环”**，不等于现有功能列表。见 [功能清单与 PRD](PRD-MVP.md)。
- 录音、白板、思维导图、AI、同步、OCR 和完整日程不是这轮 MVP 的依赖。当前界面中的部分入口是会话演示，发布前需隐藏、标明实验性或补齐能力。
- 首页图表、词频、日历日期和模拟 PDF 是样例数据；不得当成真实使用统计或已导入文件展示。

## 当前最需要验证的三个假设

1. Windows 数位板用户是否把保存可靠性、笔迹精度和导出排在学习增强功能之前：访谈 5–8 位目标用户并让其完成真实任务。
2. 现有 SVG 渲染在 1k/10k/50k 笔迹下的延迟与内存边界：按[执行计划](EDITOR-V02-EXECUTION-PLAN.md)跑可重复基准。
3. 不同驱动、Windows Ink 与显示缩放下能否稳定输入：至少覆盖两种真实设备与 100%/150% DPI。
