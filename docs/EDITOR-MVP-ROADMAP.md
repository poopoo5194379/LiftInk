# LiftInk 笔记编辑器下一阶段功能顺序

> 此文记录 V0.1 开工前的规划；本地文档、撤销/重做、图片、区域截图和置顶贴图已完成初版。当前执行顺序见 [V0.2 计划](EDITOR-V02-EXECUTION-PLAN.md)。

2026-11-02。依据当前代码：`App.tsx` 的 `Note` 只有首页与目录所需的元数据；`NoteEditorView.tsx` 是页面预览，撤销/重做按钮尚未接入；`PenInputPocView.tsx` 是不保存的输入实验台。下一阶段需要先形成真正的文档，再把实验台验证过的输入接到文档上。

## 建议顺序

| 顺序 | 用户可见能力 | 完成判据 |
| --- | --- | --- |
| 1 | 本地笔记文档、自动保存与恢复 | 关闭并重开应用后，笔迹、页面顺序、图片和标题都存在；异常退出后能恢复最近已提交操作。 |
| 2 | 撤销与重做 | 一次笔迹、整条擦除、套索移动/缩放、图片贴入/移动/缩放/删除各算一次操作；新操作清空重做分支。按钮与 Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z 工作，Windows 另支持 Ctrl+Y。 |
| 3 | 图片贴入笔记 | 文件拖入、系统剪贴板图片粘贴、已有截图贴入；图片可选中、移动、缩放、删除，笔迹能叠在图片上。 |
| 4 | 区域截图并贴入当前笔记 | 从应用内发起截图，选屏幕与区域，截完预览并放到当前页；多屏、不同缩放率、取消操作正确。 |
| 5 | 桌面悬浮贴图 | 把截图开在可拖动/缩放的置顶小窗口，支持复制、保存、贴回笔记和关闭；应用退出后窗口清理。 |
| 6 | 导出与可靠性 | 单页/整篇导出 PNG/PDF；大图片与大量笔迹仍可操作，验证内存与恢复。 |

1–3 是可用笔记编辑器的最小闭环。第 4 项是“截图进入笔记”；第 5 项是类似 Snipaste 的“贴在桌面上”。两者共用截图资源，但窗口和交互状态分开设计。

## 文档与撤销的边界

- 文档至少含 `Note → Page → Element`；元素先支持笔迹与图片，均有稳定 ID、页面坐标、层级和可见属性。图片原始文件作为独立资源保存，文档只存资源 ID 与变换参数，避免每次移动图片都复制位图。
- 笔迹采样过程是进行中状态；`pointerup` 后才提交一条 `AddStroke`。`pointercancel` 不应留下半条笔迹。擦除、套索变换、贴图分别提交 `DeleteElements`、`TransformElements`、`InsertImage` 等操作。撤销的是用户动作，不是每个采样点。
- 撤销历史按笔记实例隔离；连续拖动合并为一步。异步截图完成后才提交贴图操作，取消截图不进入历史。图片已从页面删除但仍可重做/撤销时，资源不能提前清理。
- 自动保存采用原子写入或同等安全的提交方式，明确“已保存”与“待保存”状态。第一版撤销历史可限于本次打开期间；跨重启保留历史需另做格式与容量设计。
- 这与 [Excalidraw 的 history 实现](https://github.com/excalidraw/excalidraw/blob/master/packages/excalidraw/history.ts)相符：它维护独立 undo/redo 栈，并区分持久内容变化与无需清空 redo 的临时界面状态。这里只借鉴边界，不直接移植其数据结构。

## 截图、剪贴板与悬浮贴图

- 第一步先支持粘贴和拖入图片，验证图片资源、选择框、变换与撤销链路。截图结果进入同一 `InsertImage` 路径。
- 区域截图使用系统显示器/窗口来源及用户明确发起的选区；多屏选区需要把显示器 DIP 坐标与截图像素按各自 `scaleFactor` 转换。Electron 提供 [desktopCapturer](https://www.electronjs.org/docs/latest/api/desktop-capturer/) 和 [screen](https://www.electronjs.org/docs/latest/api/screen) 的基础能力；macOS 屏幕内容抓取需要用户授权。
- 项目使用 Electron 44。其[剪贴板 API 已迁移](https://www.electronjs.org/blog/electron-44-0)：旧的 `clipboard.readImage()` 已移除，主进程的 `clipboard.read()` 是异步接口。实现时不要照搬旧版教程；renderer 只通过限定 MIME、大小和来源的最小权限桥接拿到图片数据。
- 悬浮贴图用单独的无边框窗口与 `setAlwaysOnTop`，不复用笔记画布。Electron 的[窗口 API](https://www.electronjs.org/docs/latest/api/browser-window#winsetalwaysontopflag-level-relativelevel)支持置顶，但各平台层级行为要实测。窗口只接收截图资源 ID 与必要操作，不暴露通用文件系统接口。
- 剪贴板图片、截图和导入图片统一做格式、尺寸与解码限制；将内容复制进应用资源目录，避免依赖临时文件或外部路径。全局截图快捷键和后台常驻可等核心流程稳定后再定。

## 同批应补的基础交互

- 页面新增、删除、重排和纸张模板；切页后笔迹与撤销历史归属明确。
- 撤销/重做可用状态与自动保存状态；窗口关闭前待保存内容的处理。
- 选择后复制/剪切/粘贴笔迹与图片，粘贴位置以当前视口中心或指针位置为准。
- 鼠标、笔、触控板快捷键一致性；数位板侧键映射由输入 PoC 实机结果决定。

OCR、PDF 编辑、云同步、协作和完整数据库可以在上述编辑与恢复链路稳定后再排期。
