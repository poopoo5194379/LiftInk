| --- | --- | --- | --- |
| 先处理 | **原生备份可能报成功却无法恢复。** 图片尚未加载或已缺失时，导出依赖渲染器中的 `assetUrls`，仍会写入引用该图片的文档清单。恢复端会拒绝缺件。 | 打包版向测试文档注入缺失图片引用，导出显示「已导出」，检查 ZIP 确认清单有引用、资源条目缺失。[导出与恢复](../src/renderer/src/components/LiveNoteEditorView.tsx#L554) | 导出前从文档枚举并读取必需资源。缺件时明确提示，完整备份在空测试库可恢复。 |
| 先处理 | **速记、导图和白板共用显式保存，离开时没有未保存保护。** 正在进行的语音速记离开后会停止录音并移除保存回调。导图已保存版本的未保存修改也属于会话状态。 | 打包版重现导图编辑后直接返回，未见提示且内容消失。录音卸载行为及共用保存路径为源码确认。[速记工作区](../src/renderer/src/components/QuickWorkspaceView.tsx#L48)、[共用保存入口](../src/renderer/src/App.tsx#L557) | 返回、侧栏切换、关窗均能保留草稿或请求明确处置。测试正在录音、结束后转写中和改动已存导图。 |
| 先处理 | **一篇笔记只关联最后一次录音。** 再录会替换前一音频和转写，旧笔迹时间戳仍用新录音的开始时间换算，可能跳到新录音开头。 | 源码确认。[录音保存](../src/renderer/src/components/LiveNoteEditorView.tsx#L669)、[笔迹跳转](../src/renderer/src/components/LiveNoteEditorView.tsx#L1261) | 两段录音和各自转写都能重开、定位和备份，历史笔迹定位正确。 |

| 第二批 | **文件夹可导航和移动，但目录来自固定模板。** 没有新建、改名、移动、删除分区的入口。 | 源码确认。[分区树](../src/renderer/src/App.tsx#L124)、[侧栏入口](../src/renderer/src/App.tsx#L891) | 用户可建立自己的层级，移动或改名时同步更新笔记路径。 |

| 第二批 | **PDF 的阅读能力与导出能力分离。** 可查文本层并高亮，编辑页面的底图是位图。手写编辑器导出的 PDF 把每页画面栅格化，源 PDF 文本、链接和大纲无法随该导出保留。 | 源码确认。[编辑器画布](../src/renderer/src/components/LiveNoteEditorView.tsx#L1614)、[PDF 导出](../src/renderer/src/editor/export.ts#L45) | 按产品需要决定批注 PDF 是否保留源文本和可导航结构，用可选词、链接和横向页验证。 |
| 后续 | **回收站与附件生命周期分开。** 过期清除笔记记录、文档和恢复副本。内容寻址的附件和 PDF/OCR 缓存仍占空间，当前没有安全引用清理流程。 | 打包版实测仅被过期笔记引用的图片仍可读。[清理实现](../src/main/storage.ts#L307) | 统计附件引用后清理，保护共享附件、有效备份和恢复所需资源。 |
| 后续 | **日程、目标、笔记、计时目前各自独立。** 日程和目标存在配置的 `localStorage`，没有关联笔记字段。倒计时留在单个编辑器会话，没有接到日程、提醒或任务完成。首页专注时间来自手写编辑器当前笔记的停留时长，缺少失焦/空闲剔除，Markdown 和速记也没有走同一统计入口。 | 源码确认。[本地配置](../src/renderer/src/App.tsx#L229)、[编辑器计时](../src/renderer/src/components/LiveNoteEditorView.tsx#L326)、[Markdown 和手写路由](../src/renderer/src/App.tsx#L1435) | 先明确要统计停留还是有效专注，再定义事件、目标、笔记间的关联以及整库迁移口径。 |

## 审查时的发布验收缺口

- 当前已有 Windows x64 安装候选。应用标识及发布 URL 仍用模板值，签名、升级、卸载、回滚和 macOS 尚无本轮验收证据。[打包配置](../electron-builder.yml)
- 50 MB 和 200 页是代码的导入上限。本轮横向样张通过，历史 111 页白皮书的整份导入曾在 4 分钟测试窗口内超时。大文件、长笔记、高 DPI、数位板真机和多屏截图仍需要独立验收。[大小上限](../src/shared/editor.ts#L1)
- 本轮实测使用 `LIFTINK_TEST_PACKAGED_EXE` 指向现有 `dist/win-unpacked/liftink-desktop.exe`，执行 `node scripts/check-pdf-workspace.mjs` 和 `node scripts/check-note-features.mjs`，后者使用本机合成的有声普通话样张及缓存模型。演示、离开草稿、正文搜索、附件过期和缺件备份另用隔离配置逐项探查。仅源码确认的项目已在表内标明。

## 本轮修复与复验

- **保存和迁移。** 速记与导图离开时保留本机草稿。录音按段保存，每段可单独转写。设置可备份整库，文件菜单可备份单篇。迁移使用新笔记 ID，同包内的摘录、日程和目标关系会随之更新。资源按内容哈希验证，缺件时终止备份。已识别的 PDF 页索引随新版备份迁移。附件清理保留当前笔记、回收站、有效文档副本与草稿仍引用的资源。
- **检索与工作区。** 首页、最近文件、分区、收藏和 Tags 共用正文检索数据。手写识别结果核对后进入搜索，笔迹修改后过时结果退出索引。Markdown 支持文件导入，LiftInk 导出的内嵌图片可按资产导入。白板可用手写工具，双开支持更多笔记类型，PDF 或手写来源可框选摘录。
- **PDF。** 源文件留在库内，长文档按需渲染。编辑器有原文选择模式。完整且页序未改的单个源 PDF 导出以原文档为底，保留文本、链接和原有目录。重组页或多个来源拼接时保留页面原文，原文档级目录及跨页链接不保证随重组迁移。
- **桌面工作流。** 新资料库从实际日期和空内容开始。设置接通本机资料、分区与备份。日程可关联笔记和目标，应用运行时可发指定时间的提醒。配置限时时长的日程可随手写编辑器倒计时结束而完成。专注统计在失焦或两分钟无操作后暂停。
- **回归。** `check-interaction-closures.mjs` 覆盖草稿恢复、两段录音、正文搜索、目录、日程回链、跨格式双开、备份迁移和无引用附件清理。`check-pdf-workspace.mjs` 验证横向原文选择、批注导出后的文本和外部链接。`check-note-features.mjs` 用普通话样张完成本机转写并验证扫描 PDF OCR。`check-editor-autosave.mjs` 验证坐标稳定、一分钟批量保存和关窗刷新。
- **大文件。** 用户提供的 111 页、29.8 MB 白皮书约 11 秒完成导入。「白皮书」命中后验证高亮、批注、缩放和页序变更。该样张的原始文本层未检出「采集」。解包版用 204 页、105.9 MB 的合成扫描件验证，导入约 6 秒。两次均跳到第 80 页并写入批注，重启检查保存结果。合成件测试用 Chromium 模拟 3840×2160、150% DPR。合成件衡量文件大小和页数路径，复杂扫描件和真实设备需要另测。
- **发布边界。** Windows x64 安装包已生成，解包版通过扫描 OCR、语音转写、大文件和「打开方式」回归。保留现有 Windows 安装标识以避免另建应用条目，移除了模板更新地址。真实高漫 M7、物理 4K 多屏、macOS、签名和 Windows 安装器升级、卸载与回滚仍需要对应设备、证书和独立安装环境。手写识别使用本机通用 OCR，结果需核对。
