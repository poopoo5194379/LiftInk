# Home UI 字体与视觉审计

基线：`screenshots/before-typography/`，2026-11-01。此文件记录修改前的问题与本轮视觉方向。

## 方向

- 产品：让手写笔记用户迅速找到、创建和回看内容的桌面工作台。
- 性格：安静、准确，略有温度。
- 材料：纸张、墨迹、晨光；保留原 P1 的淡紫和远山。
- 焦点：新建笔记入口与四张真实内容感的笔记缩略图。
- 识别细节：笔形 Logo 和克制的紫色选中态。

## 基线问题

- `main.css` 有两套相互覆盖的 `:root` 字体声明；早期 Inter 栈与后续 system-ui 栈并存。Tailwind 在 CSS 首部，后续自定义规则覆盖它，渲染结果不易从单条声明判断。
- 本机 Electron 的 Rendered Fonts 检查显示中文实际落在 Microsoft YaHei UI；此前没有打包中文字体。500/600 字重无法保证有真实字形，当前还允许浏览器合成。
- 主要标题在 18px/600，Logo 与主按钮 700，多处紫色图标和面积图同时强调；正文和日期却偏细。导航 15px、笔记标题 15px、日程 14px，行高与垂直对齐分散定义。
- 中文主标题被加 `0.02em` 字距；部分控件间距为 13、15、17、19px，缺乏统一节奏。
- 外层径向洗色、山景、每张卡片的玻璃高光及阴影、新建按钮渐变同时争夺注意力。近期笔记缩略图本应是视觉焦点。
- `base.css` 是模板遗留文件，当前没有被入口导入；不能把它的字体规则误当作生效配置。

## 边界

不改变 Mock 数据、Electron 进程分层、交互或 P1 要求的区域。按字体 → 对齐与层级 → 材质克制的次序修改，并在相同尺寸下重新截图。
