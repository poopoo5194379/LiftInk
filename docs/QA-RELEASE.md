# 验收、缺陷与发布手册

更新：2026-11-03。当前是开发基线，**不是已发布清单**。功能范围见[PRD](PRD-MVP.md)，指标口径见[指标定义](METRICS.md)。

## 用户语言验收清单

`通过`只表示本仓库现有自动化覆盖相应基础行为，不等于跨设备发布验收。每次候选版在下面补执行人、日期、系统和结果。

| 编号 | 用户操作 → 预期 | 当前证据/状态 |
| --- | --- | --- |
| A01 | 新建笔记→写一笔→等到“已保存”→关掉重开，笔迹和标题还在 | 基础回归已有；跨文件一致性待补 |
| A02 | 写完马上关窗，应用等待保存；若失败，默认让我继续编辑和重试 | 逻辑已实现；关窗故障对话框未自动化验收 |
| A03 | 损坏主文档但保留有效备份，重开后提示恢复；双坏时不覆盖原文件 | `check-storage-recovery.mjs` 已覆盖主要路径 |
| A04 | 图片贴入、移动、缩放→撤销/重做→重开，内容一致；资源缺失显示占位 | `check-live-editor.mjs`、`check-storage-recovery.mjs` 基础覆盖 |
| A05 | 新增/切换/删除/重排多页，退出再开顺序和内容一致 | 新增/切换已有；删除/重排未做 |
| A06 | 用真实数位板在 100%/150% DPI 下轻重压、侧键、笔尾、失焦再写，无误落墨 | 未做实机验收 |
| A07 | 在 25%/100%/400% 缩放写/擦/选，指针与内容不偏 | 真缩放未做 |
| A08 | 1k/10k/50k 笔迹文档仍可写、翻页、保存；记录 p95 帧时间和内存 | 基准尚未完成 |
| A09 | 导出单页/整篇 PDF、PNG 后和页面预览一致；原生备份在另一安装可恢复编辑 | 未做 |
| A10 | 取消截图或拒绝权限，不生成图片；多屏不同 DPI 选区准确 | 基础取消已有；设备矩阵未验收 |
| A11 | 断网仍可新建、书写、重开和导出 | 本地架构支持；候选版需实测 |
| A12 | 安装、升级、卸载与回滚后，已有笔记仍可打开 | 打包/升级流程未验收 |

建议每个候选版记录：`版本 / commit / OS / 数位板型号与驱动 / DPI / 执行人 / 日期 / A01–A12 结果 / 证据链接`。自动化入口：`npm run build`、`npm run lint`、`node scripts/check-storage-recovery.mjs`、`node scripts/check-live-editor.mjs`、`node scripts/check-navigation-editor.mjs`。

## 缺陷与风险记录（从这里开始，不用聊天记录代替）

| ID | 严重度 | 现象/复现条件 | 负责人 | 状态 | 验证标准 |
| --- | --- | --- | --- | --- | --- |
| BUG-001 | S1 | 索引与新建文档分开提交；中断时可能出现孤儿或索引悬空 | 待指派 | 待修复 | 故障注入后能恢复或明确隔离 |

| RISK-003 | S1 | 异常进程退出与断电后的最近一次已确认保存尚无实测；目前不是已复现缺陷 | 待指派 | 待验证 | 记录设备和故障注入结果 |
| BUG-004 | S2 | 首页存在过时“本次演示有效”文案、模拟日期和虚构图表 | 待指派 | 待修复 | 候选版不把样例数据伪装为真实记录 |

严重度：S0 数据大面积丢失/安全问题，阻断发布；S1 核心任务不可完成或数据风险，阻断发布；S2 有绕行方法但影响体验；S3 轻微显示/文案。状态只用 `待确认 / 待设计 / 待修复 / 修复中 / 待验证 / 已关闭`。新缺陷需附版本、步骤、实际/预期、日志或截图（脱敏）。

## 发布检查与回滚

1. **候选版冻结**：记录 commit、版本号和原生数据格式版本；关停未完成的演示入口或明确实验性标识。
2. **构建门槛**：类型检查、lint、关键 Electron 回归、A01–A12、Windows 安装版真机测试；签名、升级与卸载实测。`electron-builder.yml` 的模板标识、更新 URL、权限说明必须改完。
3. **数据门槛**：用旧版本笔记升级、备份、恢复、导出；确认回滚是否能读升级后的格式。若不可读，先实现向后兼容/迁移或禁止自动回滚。
4. **对外材料**：正式名称、简短/详细介绍、支持平台、截图、关键词、隐私政策、用户协议、支持与反馈渠道。当前名称可暂写“LiftInk（仰墨）”，其余待渠道与实际功能确定后定稿；现有截图含样例数据，不能直接当商店截图。
5. **发布后**：记录发布版本、下载链接、校验值、已知问题；按[指标方案](METRICS.md)查看三项数和真实反馈。若出现 S0/S1，停止分发并通知试用者。

**回滚步骤**：保留上一版安装包及校验值 → 停止新版本分发/更新 → 在测试机用复制的数据目录验证旧版可读 → 若格式兼容，发布旧版并说明版本与恢复步骤；若不兼容，先提供数据恢复/转换工具，不让用户直接用旧版覆盖新数据。每次迁移前复制整个 `liftink-data`（索引、notes、assets、备份）；不在原目录上尝试破坏性回滚。

## 隐私与协议的发布前门槛

当前是本地存储应用，无账号、云同步或产品遥测；截图来自用户主动操作，图片写入本机应用数据目录。正式隐私政策和用户协议需根据**最终实际行为、运营主体、分发地区和渠道**定稿并审阅，不能用模板填虚构主体或承诺。上线前核对：数据位置与删除方式、截图权限、是否上传遥测/崩溃日志、第三方服务、未成年人使用、联系方式、更新与终止条款。现在不发布法律文本。

## 反馈池与版本路线

记录格式：`反馈 ID / 日期 / 用户任务 / 设备与 DPI / 现象或请求 / 证据 / 影响人数 / 优先级 / 决定 / 关联版本`。先放仓库 issue 或本文件表格；有协作者后转 issue tracker。不要把单条反馈直接等同产品需求。

| 版本 | 目标 | 进入条件 |
| --- | --- | --- |
| MVP / v1.0 | P0 六项闭环、数据安全和 Windows 数位板验收 | A01–A12 中核心项通过，无 S0/S1 |
| v1.1 候选 | PDF 只读底图批注、连续页与书签 | MVP 真实使用数据支持需求，来源与导出规则明确 |
| v1.2 候选 | 双开参考资料、摘录回链或局部擦除 | 用户研究决定排序，不能同时承诺交付 |

Roadmap 是假设，不写发布日期。每次版本开始前根据缺陷、指标和访谈重新排序。
