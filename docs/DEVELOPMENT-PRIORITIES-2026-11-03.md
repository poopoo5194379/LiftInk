## 本轮已施工：P0-1 的首个切片

- `src/main/storage.ts` 统一目录索引和笔记文档的读写、校验、串行队列。索引新写入格式为 `{version:1,notes}`；旧数组格式仍可读取。文档维持既有 `version:1`，没有迁移旧 GTK 工程。
- 每次覆盖前把上一份有效文件原子写入 `.bak`；主文件损坏时保留 `.corrupt-<id>` 并从有效备份恢复。主文件损坏且没有有效备份时拒绝覆盖。
- 写入临时文件并同步文件内容后原子替换；关窗时等待正在执行的目录/文档写入，失败时显示继续编辑或仍要退出的选择。
- 首页目录保存失败提示保持可见并提供重试。笔记页显示恢复、缺失图片和保存失败信息；缺失图片以占位框呈现，其余内容仍可打开，保存失败可重试。
- `scripts/check-storage-recovery.mjs` 用隔离数据目录实际启动 Electron，测试旧/新索引、备份恢复、无备份损坏保护、模拟写入失败、重开以及缺失图片界面。既有编辑器回归测试继续通过。

## 仍需完成的 P0-1 工作

1. 索引和文档目前**不是单一跨文件事务**。新建时已先持久化空白文档，启动时可找回未列入目录的文档；移动、移入回收站只改索引，尚无真正的永久删除流程。后续需定义可审计的提交记录，并处理目录与文档的更复杂分歧。
2. 图片资源是内容寻址文件，但尚无引用计数或孤儿清理。要先保证撤销历史和备份仍可引用的图片不会被误删。
3. 已对“确认保存的笔迹”和“新建后尚未入索引的文档”做独立进程终止与重开验收；**写入进行中的进程终止、断电持久性**及关窗故障对话框仍未自动化验证。原子替换不等于跨文件事务或断电绝对安全。
4. 备份为上一份有效文档；高频逐笔写入会增加磁盘 IO。进入大文档阶段前应测吞吐、合并提交和检查点策略。

验证：`npm run build`、`npx eslint . --quiet`、`node scripts/check-storage-recovery.mjs`、`node scripts/check-live-editor.mjs`。这轮没有修改旧 Xournal++ 项目。

## P0-1 第二个切片：新建与孤立文档恢复（2026-11-03）

- 新建笔记改为先通过受限 IPC 创建空白文档，成功后才在 UI 中加入目录项。重复 ID 不覆盖现有文档。目录写入失败或进程在两步之间退出时，文档仍留在本地。
- 启动时扫描受控 `notes` 目录。未列入索引的文档以“恢复的笔记”加入“未分类”，保留文件原件和笔迹，提示用户核对并重命名。扫描也涵盖只有 `.json.bak` 的文档。
- 新建笔记与旧版新建笔记若目录记录存在而文档及备份都不存在，编辑页显示缺失错误并停止写入，避免以空白文档覆盖问题现场。首页演示笔记仍可首次生成文档。
- `scripts/check-document-consistency.mjs` 用隔离目录验证孤立文档（包括只剩备份文件）找回、目录回写和缺失文档保护。
- 图片资源按内容哈希复用：同一图片重复导入不再重写原文件；读取时校验哈希，损坏资源由编辑页提示；重新导入相同图片时先保留损坏副本，再原子修复资源。仍不自动删除无引用图片，因为备份与撤销历史可能引用它。
- `scripts/check-crash-recovery.mjs` 在独立工作进程中终止实际 Electron，再启动同一隔离数据目录，确认已保存笔迹与未列入目录的文档均可恢复。

本切片验证：`npm run build`、`node scripts/check-live-editor.mjs`、`node scripts/check-storage-recovery.mjs`、`node scripts/check-document-consistency.mjs`、`node scripts/check-crash-recovery.mjs`。Electron UI 测试依次运行，避免多个窗口同时争用系统鼠标输入。
