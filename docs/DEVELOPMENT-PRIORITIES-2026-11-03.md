# LiftInk 下一阶段优先级与首轮施工

日期：2026-11-03。依据[竞品对照](COMPETITOR-RESEARCH-2026.md)和[编辑器 V0.2 计划](EDITOR-V02-EXECUTION-PLAN.md)。目标是把桌面数位板笔记做成可靠、可编辑、可带走的完整流程。

| 顺序 | 工作 | 交付判据 |
| --- | --- | --- |
| P0-1 保存恢复 | 有版本的本地格式、有效备份、损坏文件隔离、保存失败提示、退出等待提交；再处理索引/文档跨文件一致性与图片资源清理 | 已确认保存的笔记重开可恢复；损坏文件不被空白数据覆盖；缺失图片可见 |
| P0-2 坐标与性能 | 固定页面坐标、实际缩放、分层绘制、视口裁剪、1k/10k/50k 笔迹基准 | 笔尖和笔迹在 25%/100%/400% 一致；测出 p95 帧时间与内存 |
| P0-3 实机数位板 | Windows Ink、侧键、悬停、压感、笔尾橡皮、失焦恢复；之后测 macOS | 用真实设备记录驱动、DPI、笔到屏延迟和异常 |

| P2 资料工作流 | PDF 底图批注、目录/书签、笔记双开、图层和内容保护 | 导入资料可批注并回到准确页面；导出保留用户选择的内容 |
| P3 学习增强 | 摘录回链、遮挡复习、计时器、笔迹关联音频；手写识别、AI、同步单独验证 | 每项功能都围绕真实学习或会议任务验收 |

## 本轮已施工：P0-1 的首个切片

- `src/main/storage.ts` 统一目录索引和笔记文档的读写、校验、串行队列。索引新写入格式为 `{version:1,notes}`；旧数组格式仍可读取。文档维持既有 `version:1`，没有迁移旧 GTK 工程。
- 每次覆盖前把上一份有效文件原子写入 `.bak`；主文件损坏时保留 `.corrupt-<id>` 并从有效备份恢复。主文件损坏且没有有效备份时拒绝覆盖。
- 写入临时文件并同步文件内容后原子替换；关窗时等待正在执行的目录/文档写入，失败时显示继续编辑或仍要退出的选择。
- 首页目录保存失败提示保持可见并提供重试。笔记页显示恢复、缺失图片和保存失败信息；缺失图片以占位框呈现，其余内容仍可打开，保存失败可重试。
- `scripts/check-storage-recovery.mjs` 用隔离数据目录实际启动 Electron，测试旧/新索引、备份恢复、无备份损坏保护、模拟写入失败、重开以及缺失图片界面。既有编辑器回归测试继续通过。

## 仍需完成的 P0-1 工作

1. 索引和文档目前**不是单一跨文件事务**。要为“新建笔记”和“移动/删除笔记”定义提交顺序与孤儿文档恢复，避免单文件有效但目录引用不一致。
2. 图片资源是内容寻址文件，但尚无引用计数或孤儿清理。要先保证撤销历史和备份仍可引用的图片不会被误删。
3. 当前测试覆盖应用重开，没有完成独立的进程突然退出与断电持久性验收；关窗故障对话框也尚未自动化验证。原子替换不等于跨文件事务或断电绝对安全。
4. 备份为上一份有效文档；高频逐笔写入会增加磁盘 IO。进入大文档阶段前应测吞吐、合并提交和检查点策略。

验证：`npm run build`、`npx eslint . --quiet`、`node scripts/check-storage-recovery.mjs`、`node scripts/check-live-editor.mjs`。这轮没有修改旧 Xournal++ 项目。
